## 编写规范

### 结构
- 沿用 v3.4 的章节结构与编号（参考 `_ref/v3.4-chapters/`），在原位置更新；新功能插入对应章节，按顺序续编小节号。
- 小节写法沿用 v3.4：目标 → 入口（菜单路径）→ 操作步骤（编号）→ 说明/注意事项，配截图。
- 每个章节文件末尾保留两个小节：
  - `## 本章变更说明（v3.4 → v4.0）`：新增 / 修改 / 删除 / 未变的小节清单。
  - `## 待确认`：环境里无法验证、权限不足、需审批通过才能截图等事项。

### 状态标签
- 环境已上线：去掉【规划】【待升级】【待上线】等标签，按环境实际写。
- 1130 版本功能：小节标题加【1130 版本】，使用原型截图，图注写「（原型示意，以上线版本为准）」。
- 环境和原型都没有：保留 v3.4 原文和原标签，不删除。

### 截图
- 存放：`images/`，命名 `chNN-序号-简述.png`（如 `ch02-03-部门成员配置.png`），原型截图加 `-proto` 后缀。
- 引用：`![图注](images/<文件名>.png)`，图下一行写「图 N-M 图注」。
- 每个操作步骤的关键界面都要截：入口页、弹窗/表单填写态、结果页。
- 旧手册截图界面已变化的必须重截；界面未变的也用环境重截，不复用旧图。

### 测试数据
- 新建的数据统一加前缀「手册示例-」。
- 不修改、不删除他人已有数据；不执行会给真实人员发消息的操作（如飞书消息类 Action）。
- 审批类操作只提交到「待审批」状态截图，审批通过后才能截的图记入「待确认」。

### 文风
- 中文，业务语言，简洁；避免「不是……而是……」句式和机械排比。
- 菜单路径写法：`知识门户 > 资源管理 > 公共空间`。

## 协作方式（GitHub）

- 正文为 Markdown，每章一个文件，图片在 `images/`，文件名与章节内引用一致。
- 修改请走分支 + Pull Request，不要直接推 `main`。
- 分支命名：`ch06-6.10-调试流程` 这种「章-小节-改动」格式。
- 提交前请确认：新增/替换的截图已在 `images/` 中、正文引用路径正确、图号在本章内连续。
- 截图规范：`chNN-序号-简述.png`，原型截图加 `-proto` 后缀；含真实员工姓名、工号、手机号、密钥的必须打码。
- 环境实测结论统一记在 `_ref/环境现状-菜单与路由.md`，菜单或路由有变化时先改这份，再改各章。
